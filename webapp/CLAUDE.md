## 빌드

프로젝트 루트에서 npm 으로 돌린다.

```bash
npm install       # http-server, concurrently
npm run build     # 아래 3개를 생성
npm start         # 빌드 후 http://localhost:5173/index.html
npm run dev       # 빌드 + 소스 감시 + 서버
npm test          # 단위 테스트 + 실제 NumPy 교차 검증
```

`npm run build`(= `node webapp/build.js`) 가 만드는 것:

| 산출물 | 용도 |
|:---|:---|
| `../index.html` | **웹서버 메인 페이지.** 소스를 각각 `<script src>` 로 불러온다. 소스를 고치면 새로고침만 하면 된다. |
| `../numpy-lab.html` | 단일 파일 배포본. 모든 CSS/JS 인라인. 서버 없이 더블클릭으로 열린다. **학생 배포용.** |
| `src/core/data.js` | 수업자료 CSV 에서 생성한 실습 데이터. |

`--watch` 로 감시, `--check` 로 문법 검사만 할 수 있다.

## 아키텍처 결정과 그 이유

**단일 HTML 파일로 빌드한다.** 교사가 학생에게 파일 하나를 배포하는 것이 목표다. 그래서 ES 모듈(`import`/`export`)을 쓰지 않는다 — `file://` 에서 모듈은 CORS 로 막힌다. 모든 파일은 `window.X` 에 붙는 순수 스크립트 IIFE다.

**브라우저에서 도는 미니 NumPy 엔진을 직접 구현했다.** 화면의 숫자는 미리 적어 둔 값이 아니라 그 자리에서 계산한 결과다. 그래서 학생이 슬라이더를 움직이면 진짜 값이 따라온다. 핵심은 NumPy 와 똑같이 **(buffer, shape, strides, offset)** 4종 세트로 배열을 모델링한 것이다. 덕분에

- 뷰(view)가 원본과 메모리를 공유하는 것을 `sharesMemory` 로 **실제로** 보여줄 수 있다
- 브로드캐스팅이 늘어난 축의 **stride 를 0 으로 만드는 것**(복사하지 않는다)을 보여줄 수 있다
- `.T` 가 strides 만 뒤집는 뷰라는 것을 값으로 증명할 수 있다

이것들은 정적인 글이나 그림으로는 전달되지 않는 개념이다.

**Pyodide 는 선택적·지연 로딩이다.** 11장에서 버튼을 누를 때만 CDN 에서 불러온다(20MB+). 인터넷이 없거나 학교 네트워크가 막으면 명확히 안내하고, 미니 엔진 탭은 그대로 동작한다. 앱의 어떤 기능도 인터넷에 의존하지 않는다.

## 엔진(`nd.js`) 검증 상태

두 겹으로 검증한다. `npm test` 가 둘 다 돌린다.

1. **`test/nd.test.js` — 단위 테스트 187건 통과.** 기대값은 NumPy 동작을 손으로 계산해 넣은 것이다.
2. **`test/cross.test.js` — 실제 NumPy 2.5.1 교차 검증 151건 전부 일치.**
   `test/gen_expected.py` 를 실제 NumPy 로 돌려 `expected.json` 을 뽑고, 엔진 결과와 대조한다.
   기대값이 손계산이 아니라 **실제 NumPy 출력**이라는 점이 이쪽의 강점이다.
   기대값을 다시 뽑으려면 `npm run test:gen`.

두 테스트가 함께 지키는 것:

- `arange(1,13).reshape(3,4)` 의 sum/mean/std/percentile/argmax
- 3차원 axis 축소: `axis=0` → `[[15,18],[21,24]]`, `axis=1` → `[[4,6],[12,14],[20,22]]`, `axis=2` → `[[3,7],[11,15],[19,23]]`
- 행렬곱 `arange(1,7).reshape(2,3) @ arange(7,13).reshape(3,2)` → `[[58,64],[139,154]]`
- 브로드캐스팅 `(4,1)+(3,)` → `(4,3)`, 늘어난 축 stride 0
- 뷰/사본 판정: 슬라이싱·reshape·ravel·T = 뷰 / flatten·copy·팬시·불리언 = 사본
- 관절염 데이터 통계 (mean 6.14875, std 4.6138, argmax(axis=1) 앞 12개)
- NumPy 출력 표기법: `print` 는 콤마 없음 `[1 2 3]`, repr 은 `array([1, 2, 3])`, float 정수값은 `[1. 2. 3.]`

**엔진을 고치면 반드시 테스트를 다시 돌려라.** 이 값들이 깨지면 앱 전체가 학생에게 거짓을 가르친다.

### Pyodide 탭(11장) 실측 결과

버튼을 누르면 CDN 에서 Pyodide 를 지연 로딩한다. **실제로 확인했다: 16초에 로딩 성공, 진짜 NumPy 실행됨.**

여기서 중요한 사실을 하나 찾았다. **Pyodide 는 WASM 32비트라 정수 기본형이 `int32`(itemsize 4)** 다. 64비트 데스크톱 NumPy 의 `int64`(itemsize 8)와 다르다. 그래서 `a.T.strides` 의 답이 이 앱 안에 세 개 있다:

| 환경 | `a.T.strides` | 이유 |
|:---|:---|:---|
| 미니 엔진 | `(1, 4)` | 원소 단위로 보여 준다 |
| 탭 2 Pyodide | `(4, 16)` | 바이트 단위 × itemsize 4 (int32) |
| 64비트 데스크톱 NumPy | `(8, 32)` | 바이트 단위 × itemsize 8 (int64) |

세 값의 *비율*은 같고 "0 이면 늘어난 축"이라는 뜻도 같다. 11장에 이 표와 설명을 넣어 두었다 — **학생이 세 숫자를 보고 혼란에 빠지지 않게 하는 것이 중요하다.** `a.dtype` 과 `a.strides` 는 탭 2 의 예제 칩이라 실제로 마주친다.

### 엔진이 근사하는 부분 (정직하게 알아 둘 것)

- `int64` 는 JS number 라서 2⁵³ 이상에서 정밀도가 다르다. 랩어라운드도 재현하지 않는다(int8/16/32 는 재현한다).
- `np.empty` 는 "메모리 쓰레기"를 난수로 흉내 낸다. 실제 값과 같을 수 없다 — 애초에 예측 불가한 것이 요점이다.
- 난수는 JS `Math.random` 기반이라 `np.random.seed` 를 줘도 NumPy 와 같은 값이 나오지 않는다.
- `matmul` 은 2차원까지만.
- float 출력의 마지막 자리는 NumPy 와 다를 수 있다.

11장에서 Pyodide 로 실제 NumPy 와 비교해 보게 만들어 두었고, 이 차이도 학생에게 밝힌다.

## 시각화 규칙 (dataviz 스킬 기준 — 어기면 접근성 위반)

팔레트는 검증된 기준 팔레트를 그대로 쓴다. `validate_palette.js` 로 라이트·다크 **양쪽 전 항목 통과** 확인했다(4슬롯 인접쌍: CVD ΔE 9.1 라이트 / 8.4 다크, 일반시야 22.9 / 19.8).

- **색 역할 배정은 전 장에서 동일하다**: A=파랑 `--s1`, B=주황 `--s2`, 결과=초록 `--s3`, 강조축=노랑 `--s4`. 학생이 색으로 역할을 익히기 때문이다.
- 크기(magnitude)는 **파랑 단일 색조 램프**만. 무지개 금지.
- 상태색(`--good`/`--critical`)은 좋음·나쁨에만. 계열색으로 재사용 금지.
- **y축 두 개 금지.** 스케일이 다르면 차트를 나눈다.
- 계열 2개 이상이면 범례 필수(`UI.lineChart` 가 자동 처리).
- 모든 차트에 **표 보기 twin**(툴팁이 값을 읽는 유일한 경로가 되면 안 된다).
- 라이트 모드에서 초록·노랑 칸은 대비 3:1 미만 → **셀 안에 숫자 라벨을 반드시 함께** 보여준다(relief rule). `UI.grid` 가 기본으로 그렇게 한다.
- 모든 점에 숫자를 찍지 않는다. 최댓값처럼 의미 있는 것만 직접 라벨.

## 흔히 깨지는 곳

- `render(root)` 는 장을 다시 방문할 때마다 호출된다. 모듈 전역에 가변 상태를 두면 두 번째 방문에서 깨진다. `render` 안의 지역 변수로 관리하라.
- `UI.grid` 는 0~3차원만 그린다. 4차원은 3차원 층 그림을 여러 벌 나열하거나 `UI.ascii` 로 그려야 한다.
- 집계 함수(`ND.sum` 등)는 **항상 ND 를 반환한다.** 스칼라가 필요하면 `.toNested()`.
- `UI.ascii` 의 칸 정렬이 어긋나면 없는 것보다 나쁘다. 실제로 눈으로 확인하라.
